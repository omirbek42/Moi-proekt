# PRD: Доска заданий для бухгалтерии (ЦА + филиалы)

## 1. Резюме

Продукт — интерактивная канбан-доска для постановки, отслеживания и контроля исполнения задач сотрудниками бухгалтерии центрального аппарата и филиалов. Основная цель — дать руководителю единый инструмент оперативного контроля сроков, статусов и обратной связи по каждому заданию, без ручного сбора отчётов по телефону и почте.

## 2. Проблема

- 32 сотрудника бухгалтерии (8 в центральном аппарате, 24 в филиалах) выполняют регламентные и разовые задачи без единой точки контроля.
- Руководитель не видит в реальном времени, что просрочено, что в работе, а что не начато.
- Нет структурированной обратной связи от исполнителя о ходе или причинах задержки.
- Нет единого еженедельного среза для планёрок и разбора проблемных точек.
- Нет быстрого способа посмотреть загрузку и статус задач одного конкретного сотрудника.

## 3. Цели и метрики успеха

| Цель | Метрика |
|---|---|
| Снизить долю просроченных задач | % просроченных задач от общего числа с активным сроком |
| Повысить прозрачность исполнения | Доля задач с обратной связью от исполнителя |
| Сократить время на подготовку отчёта к планёрке | Время от запроса до готовой сводки (целевое — мгновенно, через вкладку обзора) |
| Обеспечить персональный контроль загрузки | Доступность профиля по каждому из 32 сотрудников |

## 4. Пользователи и роли

- **Главный бухгалтер / руководитель ЦА** — ставит задачи, контролирует сроки и просрочки, проводит еженедельный разбор.
- **Сотрудники ЦА (8 человек)** — исполнители, обновляют статус, оставляют комментарии по ходу работы.
- **Бухгалтеры филиалов (24 человека)** — исполнители, аналогично ЦА, привязаны к своему филиалу.

## 5. Функциональные требования

### 5.1 Доска задач (канбан)
- Колонки статусов: «Новое», «В работе», «На проверке», «Выполнено».
- Отдельное представление «Просрочено» — задачи с истёкшим сроком и незакрытым статусом.
- Перетаскивание карточки задачи между колонками мышью меняет статус.
- Карточка задачи показывает: подразделение (ЦА/филиал), название, исполнителя, срок исполнения, индикатор наличия обратной связи.
- Фильтры: по подразделению (все / ЦА / филиалы), по статусу.
- Создание нового задания: название, описание, подразделение, исполнитель (список подтягивается по выбранному подразделению), срок исполнения.
- Валидация формы: обязательны название и срок исполнения.

### 5.2 Карточка задания (детальный просмотр)
- Открывается по клику на любую карточку задачи (с доски, из обзора или из профиля сотрудника).
- Поля: описание, подразделение, исполнитель, редактируемый срок исполнения, редактируемый статус.
- Блок обратной связи: список комментариев исполнителя с датой, поле для добавления нового комментария, кнопка отправки.
- Валидация: пустой комментарий не отправляется, выводится инлайн-ошибка.

### 5.3 Еженедельный обзор
- Отдельная вкладка с навигацией по неделям (вперёд/назад), неделя начинается с понедельника.
- Задача относится к неделе по дате срока исполнения (`due date`).
- Сводные показатели за выбранную неделю: % выполнения, число выполненных, просроченных и незавершённых задач.
- Разбивка процента выполнения отдельно по ЦА и отдельно по филиалам.
- Список «Выполнено» и список «Не выполнено» (просрочено + в работе) с именем исполнителя; клик по строке открывает детальную карточку.

### 5.4 Просмотр по сотруднику
- Отдельная вкладка с выпадающим списком сотрудников, сгруппированным по ЦА и филиалам.
- После выбора — персональная карточка: инициалы, ФИО, подразделение.
- Показатели сотрудника: всего задач, выполнено, в работе, просрочено, % выполнения с прогресс-баром.
- Полный список всех заданий сотрудника, отсортированный по сроку исполнения; клик открывает детальную карточку.

### 5.5 Статусы и автоматика
- Автоматический перевод задачи в статус «Просрочено» при прохождении срока исполнения, если статус не «Выполнено».
- Сводная статистика по всем статусам отображается на главном экране доски.

## 6. Нефункциональные требования

- Интерфейс на русском языке, понятный без обучения.
- Отклик интерфейса без задержек при переключении вкладок и фильтров.
- Адаптация под светлую и тёмную тему.
- Данные в текущей реализации хранятся в памяти сессии (прототип); для продакшена требуется постоянное хранилище (см. раздел 9).

## 7. Вне рамок текущей версии (Out of scope)

- Push/email-уведомления об истекающих и просроченных сроках.
- Ролевой доступ и авторизация (разграничение прав ЦА / филиал / сотрудник).
- Интеграция с 1С, Bitrix24 или иной корпоративной системой.
- Экспорт отчётов в Excel/PDF.
- Хранение истории изменений статусов (аудит-лог).

## 8. Рекомендации по выбору инструмента для оперативного отслеживания

Обсуждались следующие варианты для организации на 32 сотрудника:

1. **Простой старт** — Microsoft Planner / Trello: бесплатно, готовый канбан, чек-листы, комментарии.
2. **Средний уровень (рекомендуемый)** — Bitrix24: знакомый инструмент, канбан задач, диаграмма Ганта, отчёты по загрузке сотрудников, интеграция с 1С.
3. **Продвинутый уровень** — Jira / Monday.com: гибкая аналитика и автоматизация, но избыточна для регламентных бухгалтерских задач.

Дополнительные рекомендации:
- Вести резервный реестр задач в Excel/Google Таблицах, синхронизированный с доской, на случай сбоя основного инструмента.
- Настроить эскалацию: если задача не закрыта за 1 день до дедлайна — уведомление руководителю ЦА и куратору филиала.
- Обязательные поля по каждой задаче: подразделение → исполнитель → срок → приоритет → статус → комментарий исполнителя → подтверждение куратором.
- Регламент: еженедельная сводка по пятницам («открыто / просрочено / закрыто» по каждому филиалу), разбор только проблемных задач на понедельничной планёрке.

## 9. Дальнейшие шаги / бэклог

- Перевести хранение данных из in-memory прототипа в постоянное хранилище (база данных или связка с корпоративной системой).
- Добавить уведомления (email/мессенджер) об истекающих и просроченных сроках.
- Добавить ролевой доступ и аутентификацию.
- Добавить экспорт еженедельной сводки в Excel/PDF для архива и отчётности руководству.
- Рассмотреть миграцию функциональности на Bitrix24 как основной корпоративный инструмент при масштабировании.
